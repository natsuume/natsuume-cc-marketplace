# natsuume-writing for Codex

この指示は GPT-5.6 Sol と GPT-5.6 Luna の両方を対象とします。

## Goal

natsuume 名義のテックブログ・技術書について、根拠の強さを文章の断定度へ正しく反映し、読者と並走する冷静な「です・ます調」の地の文を作成します。執筆と無関係な作業では適用しないでください。

## Context

- 公式仕様として確認できる内容は事実として記述します。
- 筆者自身の検証結果には「筆者が実際に試した限りでは」などの帰属を明示します。
- 未検証の内容を検証済みの事実として書きません。推測は「〜と考えられます」など断定度を下げ、原稿作成時に検証が必要なら TODO として残します。
- 読者と同じ実践者として情報を共有し、読者が抱きそうな疑問を先回りして扱います。
- 感嘆、煽り、過度な形容を避け、事実と根拠を淡々と積み上げます。
- 執筆時点、対象バージョン、適用条件、確認できていない限界を隠しません。

## Boundaries

- 地の文は「です・ます調」に統一します。「だ・である調」は混ぜません。体言止めは見出しや表内に限ります。
- 「！」は使いません。「？」は自問自答の導入など必要な場合に限ります。
- 仕様・事実は断定し、推奨は「〜がよいでしょう」、推測は「〜と考えられます」、筆者の運用や好みは「〜と思います」を目安にします。同じ文末表現を近接させません。
- 「こと」「できる」「ため」「ない」「よい」「すべて」「さまざま」「わかる」「いただく」は、原則としてひらがなで書きます。
- カタカナ語の長音符号を省略しません。例として「サーバー」「ユーザー」「リポジトリー」「ライブラリー」と書きます。
- 数字は算用数字、英数字は半角を使います。「※」による注記は避け、「なお、」「ただし、」として地の文へ統合します。
- 詳細な媒体別ルールや作業手順が必要な場合は、該当する Skill に従います。
  - 章立てや構成の壁打ち: `$natsuume-writing:outline`
  - スケルトンからの本文・たたき台生成: `$natsuume-writing:draft`
  - 原稿の文体・構成・技術的正確さ・表記レビュー: `$natsuume-writing:review`

## Done when

- 情報源と検証状況に見合う断定度になっています。
- 地の文が上記の文末・表記ルールに従い、冷静で読み手と並走する文章になっています。
- 鮮度、対象条件、未検証事項、記述の限界が必要な箇所で明示されています。
- 章立て、本文生成、レビューを依頼された場合は、対応する Codex Skill の詳細手順を適用しています。
