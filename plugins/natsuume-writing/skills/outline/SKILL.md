# outline

技術記事・技術書の**章立て決定フェーズ**の詳細手順です。常時注入 (SessionStart) が配送する執筆ルール要点 (`rules/core-summary.md`) を前提に、本 skill は壁打ちで章立て・セクション構成を確定し、対象ファイルにインファイルスケルトンを書き込むまでの具体的な手順を提供します。

この `SKILL.md` を含む `skills/outline/` の 2 階層上を `<plugin-root>` として解決する。通常の Skill 実行では hook 用の `${CLAUDE_PLUGIN_ROOT}` が設定される保証はないため、reference file は実パスから解決する。

以下の「ユーザーに確認」は `AskUserQuestion` を使い、未確定事項を推測で埋めない。

対象は Markdown ファイルのみです (ReVIEW 形式の技術書原稿はスコープ外のため扱いません)。

フローは次の 3 段階です。各段階を順番に進め、前段階が確定するまで次段階には進まないでください。

## 1. 前提の確定

対象ファイル・テーマ・想定読者・媒体・記事タイプを確定します。

1. **対象ファイルの確認**。ユーザーの指示やここまでの会話から書き込み先のファイルが明らかな場合はそれを使います。未指定の場合は下記「対象ファイル未指定のとき」の手順に従います。
2. **前提項目の確認**。次の項目をユーザーに確認します。引数やここまでの会話から自明な項目は質問を省略してよいです。
   - テーマ (記事・章で扱う主題)
   - 想定読者
   - 媒体: 書籍 / 企業ブログ / 個人ブログ のいずれか
   - 記事タイプ: 技術解説 / 検証レポート / 体験レポート のいずれか (媒体 = 書籍 のときは省略可)

### 対象ファイル未指定のとき

テーマから妥当なファイル名を提案し、ユーザーの確認を得てから新規作成します。ユーザーが別のファイル名を望む場合はそれに従います。

### 対象ファイルにすでに本文があるとき

対象ファイルが既存の場合は内容を読み、見出し・HTML コメント・空行以外のテキスト (地の文) が存在するかを確認します。存在する場合は、**書き込まずに**ユーザーへ扱いを確認します。選択肢は次の 2 つです。

- 中止する (このセッションでは書き込みを行わない)
- 既存の構成を尊重した追記を行う (壁打ちの結果を、既存の章立てを壊さない形で追加する)

見出し・HTML コメント・空行しかない (= 過去にこの skill で作られた未執筆のスケルトンである、または単に空である) 場合は本文なしとみなし、通常どおり壁打ちに進んでよいです。

## 2. 壁打ち

`<plugin-root>/rules/writing-rules.md` を読み込み、確定した媒体・記事タイプに対応する構成の型 (記事タイプ別の導入パターン、章冒頭定型、数の予告 → 列挙 → 回収、まとめの扱い) を把握します。

その型を反映した章立て・セクション構成案を複数提示し、ユーザーの選好を確認しながら段階的に収束させます。1 回のやり取りで確定させようとせず、粒度・順序・見出し文言について必要な分だけ往復してください。

壁打ちの途中でユーザーが中断した場合 (別の作業に移る、セッションを終了する等)、ファイルには何も書き込みません。次段階に進むのは、章立てが確定したと判断できたときだけです。

## 3. スケルトン書き込み

構成が確定したら、対象ファイルへの書き込みを 1 回だけ行います。複数回に分けて書き込まないでください。

書式は次のとおりです。

```markdown
# 記事タイトル

<!-- outline: 媒体=個人ブログ / 記事タイプ=技術解説 / 想定読者=◯◯ -->

## セクション見出し
<!-- このセクションで書くべき内容・意図・入れる予定の要素 (図・コード・比較表など) -->
```

- `outline` コメントはファイル先頭 (タイトル直後) に 1 つだけ置きます。セクションごとに増やさず、媒体・記事タイプ・想定読者はここに集約します。
- 媒体 = 書籍 のときは `記事タイプ=` の部分を省略できます (例: `<!-- outline: 媒体=書籍 / 想定読者=◯◯ -->`)。
- 各セクション見出し直下に、そのセクションで書くべき内容・意図・入れる予定の要素を説明する HTML コメントを 1 つ置きます。
- 「既存構成を尊重した追記」を選んだ場合は、既存の見出し構造を保持したまま、不足しているセクションへのコメント追加や新規セクションの追記に限定します。既存の地の文を書き換えたり削除したりしません。
