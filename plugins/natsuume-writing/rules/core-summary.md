これは natsuume-writing plugin の執筆ルールの要点です。文章作成一般のルールと、natsuume 名義の技術文書のルールの 2 層で構成されます。文章を書かない作業では無視してよい内容です。

## 文章作成一般のルール

成果物として書く日本語の文章すべて（ドキュメント・README・コードコメント・PR や issue の本文・コミットメッセージ・メール・記事など）に適用します。チャットでの応答は対象外です。文体・人称・表記はこの層では定めず、既存文書の書式やプロジェクトの規約がある場合はそちらを優先します。

- 読者の理解に必要な分だけ整える。分類・対比・命名・強調・道案内は読者が本文から自力で追えない箇所にだけ使い、文章全体で同じレトリックや論証の型を反復しない
- 「A ではなく B」の対比、その場での概念命名、何でも分類・列挙する構成、段落ごとの決め台詞を重ねない
- 予告・構造の実況・意味の先回り・発見や転回の演出のように、削っても情報が失われないメタ文を書かない
- 太字は危険な警告と用語の初出に限る。直訳的な言い回し（「効く」「刺さる」「倒れる」「壊れる」等）で内容をぼかさず、具体的な語で書ける箇所では具体的な語に置き換える
- 次の語は人間の文章ではほとんど使われない（見直し候補の一覧の「強く抑制する語」）ため、原則として使わない。使うのは具体的な語で書けない理由がある場合に限る: 〜に丸投げする、線引き、〜という役割、司令塔、積み上がる、積み重なる、構図、導線、棚卸し、ブレる、主役、泥臭い、〜に逃がす、〜を左右する、横展開、設計判断、構造的、核心、根本原因、判断基準、明文化する、出発点、教訓、中核、〜する力、属人化、暗黙知、設計方針、再現可能、統制、精度が上がる、破綻する、判断軸、正本、設計意図

ドキュメント・記事・PR の説明のようにまとまった文章を書く・推敲するときは、この plugin の `rules/` ディレクトリ（SessionStart hook がこの本文の末尾に付ける `(参照パス)` 行の絶対パス）にある `general-writing.md`（文章作成一般のルール全文）と `expression-watchlist.md`（見直し候補の語の一覧）を読み込んで従ってください。

文書ファイル（Markdown やプレーンテキストのドキュメント・README・記事など）と PR・issue の本文の地の文を書いた・書き換えたときは、完了とする前に `/natsuume-writing:review` を 1 回実行し、指摘を反映してから完了としてください（`general-writing.md` セクション 5）。PR・issue の本文は、投稿前の下書きを一時ディレクトリのファイルに書き出してレビューし、反映した本文を投稿します。コードコメントとコミットメッセージ、地の文を変えない編集（バージョン番号の更新など）、作業用のファイル（引き継ぎ文書・作業メモなど）は対象外です。

## natsuume 名義の技術文書のルール

natsuume 名義の技術文書（テックブログ・技術書・社内技術文書）の地の文には、上記に加えて以下を適用します。ただし社内技術文書では、文末は常体（「〜する」「〜した」「〜だった」）と体言止めで書き、箇条書きを中心にします。一人称・読者への働きかけ・構成とコードの定型・シグネチャ表現は使いません（`writing-rules.md` の社内技術文書プロファイル。下記の文末表現の要点より優先します）。

### 通底原則（迷ったらここから導出する）

1. 断定度は情報源に比例させる。公式仕様は断定し、自分で検証した事実は「筆者が実際に試した限りでは」と帰属を明示し、未検証の推測は婉曲表現に落とす
2. 読者と並走する。同じ実践者として情報を共有する距離感を保ち、読者が実際につまずきそうな疑問は先回りして代弁する。反論や例外を網羅的に処理して議論を閉じようとはしない
3. 冷静・抑制。感嘆・煽り・過度な形容を使わず、淡々と事実と根拠を積む
4. 鮮度と限界を明示する。執筆時点・バージョン・条件を明記し、情報が古くなる可能性と自分の記述の限界を隠さない
5. 読者の理解に必要な分だけ整える（文章作成一般のルールと同じ）

### 文末表現の要点

- です・ます調のみ（だ・である調を混ぜない。体言止めは見出し・表内のみ可）
- 「！」は使わない。「？」もほぼ使わない（例外は自問自答の導入のみ）
- 断定度の使い分け: 仕様・事実は断定、推奨は「〜がよいでしょう」、推測は「〜と考えられます」、筆者の運用・好みは「〜と思います」
- 同一の文末表現を近接させない（「でしょう」を含む文を 2 文連続で置かない等）

### 表記の要点

- ひらがなに開く: こと / できる / ため / ない / よい / すべて / さまざま / わかる / いただく
- カタカナ語の長音符号は省略しない（サーバー / ユーザー / リポジトリー / ライブラリー 等）
- 数字は算用数字（漢数字は使わない）。英数字は半角
- 「※」は使わない。注記・補足は「なお、」「ただし、」で地の文に統合する

### 詳細ルールへの案内

ここにあるのは要点のみです。技術文書の執筆作業（章立て・たたき台作成・推敲・レビュー）では、同じ `rules/` ディレクトリにある `writing-rules.md`（共通コア全文 + 書籍/ブログ/社内技術文書の媒体プロファイル）を読み込んで従ってください。章立ての壁打ちは `/natsuume-writing:outline` を、スケルトンからのたたき台生成は `/natsuume-writing:draft` を使用してください。原稿のレビューには `/natsuume-writing:review` を使用します。review は技術文書以外の文章にも使え、その場合は文章作成一般のルールで判定します。
