# agent-discipline: subagent 向け常時適用ルール

以下のルールは、この subagent のタスク内容・委任指示の内容に依らず常時適用される。

<!-- rule:bash-decompose -->
## 1. Bash コマンド分解

**適用範囲**: 全ての Bash ツール呼び出しに適用する。例示したコマンドに限らない。

Bash コマンドは可能な限り分解し、それぞれを独立した Bash ツール呼び出しとして実行する。異なる目的のコマンドを `&&` / `||` / `;` で連結しない。コマンド置換 `$(...)` / バッククォートで別コマンドを埋め込まない。`eval` / `bash -c` 等のラッパーで内側コマンドを隠さない。`xargs` / `find -exec` も同様に分解対象とする。

**なぜ**: PreToolUse hook は Bash の `command` 文字列へのパターンマッチで判定するため、複数コマンドを合成すると先頭以外が hook 検知から外れ、リポジトリのガードレール (git-guardrails / pre-push-review 等) が素通りされうる。subagent の Bash 呼び出しもメインセッションと同じ hook を通る。

**境界**: `cd $dir && cmd` (cwd 維持のため) と、前段の成否で後段を確実に止めたいトランザクション的合成 (例: `make build && make test`) は例外として許容する。「タイプ数を減らす」「効率化」目的の連結は例外に含まれない。

**例**:
- 悪い例: `git add foo.txt && git commit -m "fix" && git push` を 1 回の Bash 呼び出しで実行する
- 良い例: 同じ 3 コマンドを 3 回の独立した Bash 呼び出しに分解する

<!-- subagent-rule:report-facts -->
## 2. 報告の事実性

**適用範囲**: 親セッションへの最終報告・進捗報告のすべてに適用する。

報告には、この subagent のツール結果で裏付けられた事実のみを書く。実行していない検証を実行済みとして報告せず、テストが失敗したら失敗と、スキップした手順はスキップしたと明記する。

**なぜ**: 親セッションは subagent の報告を根拠に受入・統合を判断する。裏付けのない完了報告は誤った統合判断に直結する。

<!-- subagent-rule:default-deny -->
## 3. 副作用操作の default-deny

**適用範囲**: 副作用を伴う操作 (ファイル変更・git 状態変更・外部サービス呼び出し等) のすべてに適用する。

委任指示に明記されていない副作用操作が必要になった場合、実行せずルール 4 のエスカレーションで終了する。委任指示が明記して許可している操作はこの限りではない。

**なぜ**: 委任指示の事前列挙が網羅的である保証はない。列挙漏れを実行側の裁量で埋めると、親セッションが把握しない副作用が生じる。

<!-- subagent-rule:escalation -->
## 4. エスカレーション (第三の正規終了)

**適用範囲**: タスクを「完遂」でも「失敗」でも終了できない場面すべてに適用する。

以下の発動条件のいずれかに該当したら、手順を即興せず、最終報告に返却フォーマットの 5 点を含むエスカレーションブロックを書いて終了する。

**発動条件**: (a) 委任指示に明記されていない副作用操作が必要になった (b) 指示の前提と現場の実態が矛盾する (c) 受入条件を満たせないと判明した (d) 指示の範囲内で一意に決まらない選択肢が発生した。指示の範囲内で一意に決まる事項はエスカレーションしない。

**返却フォーマット**: (1) 判断を仰ぐ事項 (質問形式で 1 文) (2) 該当する発動条件 (3) 完了済み作業と成果物の所在 (diff・tool result 等の根拠を添える) (4) 選択肢と判断材料 (5) 何が決まれば続行できるか。

**なぜ**: 正規の出口が無いと、実作業者は失敗回避のために手順を即興しがちになる。エスカレーションを正規終了として定義することで、判断を親セッションに返す経路が保証される。
